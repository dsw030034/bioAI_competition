# 当前项目代码逻辑说明

本文档解释当前这套代码的总体思路、各模块职责和运行方式，帮助快速理解“为什么这么写”。

## 1. 总体目标

当前代码不是完整的 Nav1.8 实验级药物生成平台，而是按照 README 和 week2 方案的方向，先搭出一个可运行的原型：

1. 读取种子分子
2. 生成候选分子
3. 用二维性质做过滤
4. 计算奖励分
5. 输出候选库和评估指标
6. 生成 3D 构象，并通过 ExternalProcess 接入 REINVENT4

核心目标是：把“生成 → 过滤 → 输出”的闭环先跑通，后续可以直接接到更强的 3D docking、选择性建模和 RL 迭代中。

## 2. 代码结构

### 2.1 `navgen/config.py`

职责：读取配置文件，解析筛选参数。

- `FilterConfig`：定义分子筛选阈值，如：
  - MW
  - LogP
  - TPSA
  - QED
  - SA
  - similarity_min
  - required_smarts
  - num_confs
  - max_candidates
- `load_config()`：从 JSON 配置中加载参数，并把路径相对配置文件解析。

意义：保证所有筛选参数集中在配置文件里，后续只需要改 JSON，不用改代码。

### 2.2 `navgen/generation.py`

职责：实现种子附近的候选构造。

当前版本的生成逻辑是“模板式 amide 替换”策略：

- 读取种子 SMILES
- 选择一组候选砌块 block
- 通过一个简单的反应模板近似生成新分子
- 为每个分子生成唯一 `candidate_id`
- 记录来源、路线、反应模板等信息

原始思路对应 README 里的：

- scaffold-conditioned generation
- seed nearby generation
- amide replacement / scaffold expansion

即：保留一部分核心骨架，改变另一侧的片段，生成类似但不完全相同的分子。

目前的实现是工程化的最小可用版本，不是复杂的深度生成器，而是把生成框架跑起来。

### 2.3 `navgen/scoring.py`

职责：对分子做筛选和打分。

它处理了几个关键点：

- 计算物理化学性质：MW、LogP、TPSA
- 计算 QED
- 计算 SA（合成可得性）
- 判断是否有目标 SMARTS 基团（如 amide）
- 计算与种子分子的相似度
- 计算一个简化 reward：
  - 二维药物相似性优先
  - 膜性质偏好
  - 最终输出 reward 值
- 可选叠加 Site C/Nav1.5 对照代理分数：
  - `site_c_score`：中心腔体锚点、芳香疏水片段和尺寸匹配的二维代理
  - `fenestration_score`：芳香环、卤素、疏水性和柔性的 fenestration 入口代理
  - `nav15_counter_penalty`：对通用孔道阻断样化学特征的保守惩罚
  - `selectivity_proxy`：Nav1.8 代理分数减去 Nav1.5 counter-screen 惩罚

这些分数来自 `data/nav18_site_c_rules.json` 中记录的文献证据（7WE4/A-803467、
S6 IV 突变研究以及 Nav1.5 quinidine 结构）。它们只用于排序和 REINVENT4
早期探索，**不是 docking、结合自由能或实验选择性结果**。Site C 的关键证据位点
包括 Gln355、Phe386、Thr397、Gly1406、Phe1710、Met1713 和 Tyr1717；其中
Thr397/Gly1406 是远端别构选择性线索，不能被二维分数伪装成直接接触。

也就是说：

- 先判断是否“合法”
- 再看是否“有用”
- 然后给出 reward 供后续 RL / 选择性评分接入

### 2.4 `navgen/conformers.py`

职责：生成 3D 构象，输出 SDF 文件。

核心逻辑：

- 用 RDKit 进行 conformer embedding
- 用 MMFF / UFF 做能量最小化
- 保存每个候选分子的多个构象
- 选择最低能量构象输出 `best_conformers.sdf`
- 记录失败状态（例如 embedding 失败、优化失败）

这部分对应 README 中提到的：

- 多构象生成
- 失败处理
- 3D 输出文件

### 2.5 `navgen/pipeline.py`

这是整个项目的核心编排器。

它负责：

1. 读取配置
2. 读取种子库
3. 遍历每个种子并生成候选
4. 对候选进行筛选
5. 记录到 SQLite 数据库
6. 导出 CSV / JSON / SDF
7. 生成 metrics.json 和 manifest.json

这个模块决定了完整工作流的最终结果。

### 2.6 `navgen/reinvent.py`

职责：准备 REINVENT4 所需配置文件。

它并不真正运行 REINVENT4，而是生成配置模板：

- sampling.toml
- staged_learning.toml

并写入外部奖励接口入口：

- `python -m navgen score-stdin`

这对应 README 里的：

- REINVENT4 接口
- Mol2Mol prior
- ExternalProcess 回传 reward

### 2.7 `navgen/cli.py` and `navgen/__main__.py`

职责：让代码可以用命令行调用。

支持命令：

- `generate`
  - 生成候选库
- `prepare-reinvent`
  - 生成 RL 配置参数文件
- `score-stdin`
  - 从标准输入读取 SMILES，使用与 pipeline 相同的 scorer
  - 输出 REINVENT4 ExternalProcess 需要的
    `{"version": 1, "payload": {"nav18_reward": [...]}}`
  - 保留输入顺序和长度，非法或空分子奖励为 0

因此可以很方便地接到外部模型或 RL 流程中。

## 3. 运行入口

项目根目录提供了 `pyproject.toml`，支持如下方式启动：

```powershell
Set-Location "F:\大三秋\神秘比赛"
python -m navgen generate --config configs/demo.json --output outputs/my_first_run
```

这条命令会：

- 读取 `configs/demo.json`
- 读取 `data/seeds.smi`
- 生成候选分子
- 执行过滤
- 输出候选结果

## 4. 生成的数据文件

在输出目录中，通常会得到：

- `candidates.csv`：通过筛选的候选分子
- `rejected.csv`：被筛掉的分子
- `molecules.sqlite`：数据库
- `manifest.json`：配置和实验信息快照
- `metrics.json`：实验衡量指标
- `conformers.sdf`：全部构象
- `best_conformers.sdf`：最佳构象
- `conformer_status.json`：构象生成状态

这正对应 README 中描述的“候选库/评价/输出交接”流程。

## 5. 当前这套代码的价值

当前版本的价值不在于“绝对正确的药物设计”，而在于：

- 把流程拆成了可以持续扩展的模块
- 把生成、筛选、评价、输出、接入接口分开了
- 对 README 的思路做了工程化落地
- 后续可以直接接：
  - docking
  - active learning
  - selectivity model
  - RL reward loop
  - REINVENT4

## 6. 本次参考资料驱动的新增内容

### 6.1 Site C 方向

`configs/site_c_reference.json` 是在不改写 `configs/demo.json` 的前提下新增的实验入口。
它保留原有 seed-nearby 生成和 protein-word 评分，同时启用 Site C 代理。文献支持的
化学假设是：A-803467 位于中央腔体，羰基可作为 Gln355 附近的氢键锚点，S6 IV 的
Phe1710/Tyr1717 和 fenestration 周边提供疏水环境；Nav1.8 的亚型差异还可能受
Thr397/Gly1406 远端别构网络影响。2009 年 S6 突变研究和 Nav1.5-quinidine 结构
同时提醒我们，通用孔道阻断样分子可能带来心脏安全性风险，因此新增了保守的
Nav1.5 counter-screen 代理。

### 6.2 运行新实验

```powershell
python -m navgen generate --config configs/site_c_reference.json --output outputs/site_c_reference_run
```

旧的 `outputs/my_first_run` 和 `outputs/protein_word_run_v3` 不会被覆盖。新输出的
`candidates.csv` 会增加 `site_c_score`、`fenestration_score`、
`nav18_proxy_score`、`nav15_counter_penalty` 和 `selectivity_proxy` 列。

### 6.3 REINVENT4

现在 `score-stdin` 不再返回固定的演示分数，而是读取项目配置并调用同一套 descriptor、
protein-word 和 Site C scorer。例如：

```powershell
"C(=O)Nc1ccccc1" | python -m navgen score-stdin --config configs/site_c_reference.json
```

项目新增了两个 Windows 脚本：

```powershell
# 下载官方 Zenodo prior（约 80 MB，已下载到 models/reinvent4/）
.\scripts\download_reinvent_prior.ps1

# 创建 Python 3.11 的 REINVENT4 环境并安装 CPU 版本
.\scripts\setup_reinvent4.ps1 -Backend cpu
```

GPU 用户可根据本机 PyTorch/CUDA 版本改用 `-Backend cu126` 或其他脚本支持的
后端。脚本会从官方 REINVENT4 仓库安装，不会把 80 MB prior 或第三方源码提交到
GitHub。

使用官方当前配置格式生成采样和 RL 配置：

```powershell
python -m navgen prepare-reinvent `
  --config configs/site_c_reference.json `
  --prior models/reinvent4/mol2mol_medium_similarity.prior `
  --output outputs/reinvent_site_c_reference `
  --device cpu `
  --num-smiles 100
```

然后在 REINVENT4 环境中调用：

```powershell
conda run -n reinvent4 reinvent outputs/reinvent_site_c_reference/sampling.toml
conda run -n reinvent4 reinvent outputs/reinvent_site_c_reference/staged_learning.toml
```

`sampling.toml` 和 `staged_learning.toml` 已改为 REINVENT4 官方当前的
`run_type`、`[parameters]`、`[learning_strategy]` 和 `[[stage]]` 格式。第一阶段
使用 REINVENT4 内置的 QED/MW/LogP 组件，先验证 prior、Mol2Mol 采样和 DAP RL
链路；`navgen score-stdin` 仍可用于对采样结果做完整的 Site C/protein-word
二次评分。这样不会把尚未注册为 REINVENT4 原生 scoring component 的代理函数
伪装成已经进入 RL 的奖励。

项目侧的 `reinvent_native_metrics()` 同时复现 QED、MW/LogP 双 sigmoid 和
geometric mean。`configs/site_c_reference.json` 将其以
`reinvent_metric_weight=0.15` 纳入项目 reward，因此原 pipeline、ExternalProcess
和 REINVENT4 原生组件采用一致的指标语义。REINVENT4 生成 CSV 后，可执行：

```powershell
python -m navgen score-reinvent-file `
  --config configs/site_c_reference.json `
  --input outputs/reinvent_site_c_reference/sampling_mol2mol.csv `
  --output outputs/reinvent_site_c_reference/sampling_scored.csv
```

该命令保留 REINVENT4 的 `NLL` 等列，并追加项目 reward、Site C、protein-word
和 Nav1.5 counter-screen 指标，便于比较“REINVENT4 原生评分”和项目完整评分。

本次已在 Windows CPU 环境完成真实验证：REINVENT4 4.8.24 使用官方
`mol2mol_medium_similarity.prior` 生成了 4 个候选；随后 DAP staged learning
运行到第 6 步并提前达到阶段阈值，产出 `rl_run_1.csv` 和 `stage1.chkpt`。
日志中的 prior hash warning 不阻止采样或训练，但提示该 prior 的序列化 hash
来自不同版本的 xxhash；后续固定环境版本时应重新核验。OpenEye/ChemProp 的
可选插件未安装，本项目当前配置不依赖它们。

## 7. 当前版本的限制

当前代码仍然属于“原型工程”，主要限制有：

1. 生成逻辑较简化，不是真实的高质量 de novo 生成模型
2. 2D 过滤是工程先验，不等于真实药理筛选规则
3. 3D 构象生成是基础版本，不做复杂蛋白受体约束
4. Vina docking 编排接口已接入，但在获得真实受体 PDBQT、配体 PDBQT 和 box 坐标前不会执行或伪造 docking 结果
5. Site C/Nav1.5 分数仍是二维 proxy，尚未替代真实 docking、电生理或配对 ΔΔG
6. REINVENT4 CPU/GPU 环境和 prior 已有安装脚本；完整采样/RL 仍需在本机执行验证

所以它应当被视为：

- 一个“可运行的分子生成框架原型”
- 不是最终可发布的药物发现系统

## 8. 后续最合理的发展方向

如果继续做下去，最合理的顺序建议是：

1. 先把生成逻辑升级成更像 scaffold-conditioned generator
2. 再接真实 docking / 受体口袋筛选
3. 加入 Nav1.8 vs Nav1.5 selectivity score
4. 再接 REINVENT4 RL 奖励回传
5. 最后做 active learning / iterative seed expansion

## 8. 本次增量：protein-word-inspired reward

在不推翻原有生成器的前提下，当前版本新增了 `navgen/protein_rules.py`：

- 从配置的蛋白序列中提取连续 protein words；
- 按 word 的疏水、带电、极性和芳香特征建立可读的 fragment 配对规则；
- 根据候选 SMILES 中的芳香、卤素、胺、极性和羰基片段命中情况计算 `protein_word_score`；
- 将该分数以可配置权重加入原有二维 reward；
- 输出 `protein_word_rules.json` 和带完整解释字段的 `candidates.jsonl`。

这是一版可运行的解释性原型，不等同于论文中基于大规模结合数据、protein-wordwise/ESM-2 和 Integrated Gradients 学得的 PWRules。当前 demo 的序列也明确标记为演示序列，不应当解释为 Nav1.8 的真实序列或生物学结论。接入真实 Nav1.8/ Nav1.5 序列和配对活性数据后，才应替换为数据驱动的规则学习与选择性评分。

## 10. A-803467 种子与 Nav1.5 对照对接

复核上一批结果时发现旧生成函数把输入 seed 仅用于记录，实际结构固定拼接为苯甲酰苯胺。
因此新增了 seed-local 类似物生成路径：当输入种子含有可识别的芳基氯或芳基甲氧基时，
枚举保留母核的氯替换/去除、CF3 替换及甲氧基局部改造；原有其他种子仍可走旧模板路径。

本轮使用 `data/seeds_a803467.smi` 中由用户提供的 A-803467 结构作为唯一 seed，通过
`configs/a803467_site_c.json` 运行生成，候选输出到全新目录
`outputs/a803467_nav18_nav15_round1/`。配置不再使用演示用 `demo_protein.fasta`；
本轮保留结构规则驱动的 Site C proxy，未计算演示序列的 protein-word proxy。本轮产生
12 个唯一 seed analogues，其中 7 个通过当前过滤、5 个被过滤。生成脚本代码位置为
`navgen/generation.py`；候选都保留 A-803467 的核心骨架，主要改变芳基氯及甲氧基取代。

Nav1.5 counter-screen 使用 Nav1.5 配体结合结构 6LQA 的链 B。新增
`scripts/clean_nav15_chain_b.py`，仅保留完整标准氨基酸，去掉配体/糖脂等 HETATM，
